# Review of the proposed Tea Leaf fixes

Reviewed against the checkout of that date. No experiment code, configuration, data, or run artifacts were changed during this review.

**Status (after the review).** We kept this review as the dated record it is; it describes
the v1 code. The training-affecting decisions it calls for were settled before any v2 run,
as it recommends. We kept the EMA decay (0.9998) and changed the following: post-final-LayerNorm Stage-4 tokens, RNG-neutral head initialisation, the
weight-decay exemption for norms, biases and gates, tail-weighted gradient accumulation,
scheduler, and EMA stepping only on non-skipped AMP updates, and full RNG restoration on
resume (see `src/training_contracts.py`). We started a new campaign (`tea_leaf_v2`) for them
and kept v1's `R0_s42` under its original protocol, in `results/fresh/`, rather than mixing
it in. The Tier 2 and Tier 3 items were fixed or disclosed as listed in the README's
"What changed in v2".

## Verdict

The plan identifies substantial real problems, but should not be implemented verbatim. It mixes confirmed defects, reasonable protocol choices, speculative effects on accuracy, and several incorrect factual claims. In particular, the proposed “any time” treatment of optimizer, accumulation, and resume changes is inappropriate: these can change trained checkpoints and belong in a versioned campaign decision.

Evidence comprises source inspection, PowerShell calculations over the manifests and run logs, file/hash checks, and upstream source inspection. The available `python` command is an inaccessible Windows application alias, and this checkout contains no virtual environment. I did not execute PyTorch constructor/gradient tests, training, or the Python pipeline. The recorded environment reports timm 1.0.29; I checked upstream Swin source but did not independently execute that recorded installation. Only R0_s42 has local run artifacts; the quoted C1 epoch-16 observation and exact constructor weight sums cannot be independently verified here.

## Tier 0

| ID | Verdict | Evidence and correction |
|---|---|---|
| T0.1 | Confirmed structural defect relative to a standard Swin control | `src/train_token_models.py:479` hooks the stages; line 502 discards the full Swin output; lines 536–538 return the captured pre-final-norm features. The classifier pools these tokens. Upstream Swin applies `self.norm` after the stages. The final norm's parameters remain counted, but are disconnected from the classification loss. Restore a documented normalization position consistently across token arms. Normalizing before the token module and normalizing after it are different designs; do not treat them as interchangeable fixes. Parameter-count checks alone cannot verify the correction. |
| T0.2 | EMA arithmetic confirmed; diagnosis and mandatory remedy overstated | Both recipes attempt 96 updates/epoch. At decay 0.9998, half-life is **36.0978 epochs**, the initial coefficient is **0.195506 at epoch 85**, and **0.146579 at epoch 100**. R0's best logged validation Macro-F1 is epoch 85. Constant EMA initialized from model weights is a valid estimator, not automatically a bias-correction bug. The coefficient applies to pretrained weights as well as random head weights; “contamination” is misleading. Early train/raw versus validation/EMA metrics cannot isolate the cause of the gap. A best epoch of 100 is evidence to examine convergence, not proof that more training improves generalization. Warm-up, lower decay, or retaining the existing protocol are decisions to settle using validation evidence. If EMA changes, restart affected comparisons, including R0. Do not simply divide an EMA initialized at theta_0 by 1-d^t as if it were zero-initialized. |
| T0.3 | RNG mismatch confirmed structurally; justification partly incorrect | Both constructors build optional modules before the shared classifier. Same seed therefore does not promise identical classifier weights. With zero workers, transform draws also share the main process RNG. However, **the backbone is not frozen**: parameters are passed to AdamW without freezing the backbone. The claim that head initialization dominates variance is unsupported. Same-seed bootstrap pairing here is pairing of test images, not proof of matched training randomness. Isolate classifier initialization and augmentation RNG explicitly if matched randomness is intended. Merely setting workers to 2 does not solve checkpoint/resume reproducibility, and globally reseeding inside a constructor has side effects. |

Upstream reference for T0.1: [timm Swin forward_features](https://github.com/huggingface/pytorch-image-models/blob/main/timm/models/swin_transformer.py). This establishes the upstream control flow, not a runtime test of the saved environment.

## Tier 1

| ID | Verdict | Evidence and correction |
|---|---|---|
| T1.1 | Confirmed loss-definition mismatch | Swin trains with smoothing at line 1282 and evaluates without it at line 1364; token evaluation includes smoothing at line 1249. Comparing those loss curves as though they used one objective is wrong. But unsmoothed evaluation cross-entropy is a legitimate metric, and the train/validation gap is not attributable solely to smoothing: augmentation, dropout, EMA, and averaging during the epoch also differ. Standardize or clearly label the metrics. Macro-F1 selection is unaffected. |
| T1.2 | Exception-safety defect confirmed; claimed auto-resume corruption incorrect | Both evaluators lack a `finally` to restore raw parameters. Nested `apply_shadow()` also overwrites the backup. This can corrupt continued use of the same in-memory trainer after a caught exception. However, the normal CLI propagates evaluation errors; checkpoints are saved after successful evaluation. A new `--auto_resume` process loads the previous checkpoint, not the abandoned in-memory EMA parameters. EMA-of-EMA after an ordinary crashed validation is not demonstrated by this code. |
| T1.3 | Confirmed, with narrower wording | The global UserWarning/FutureWarning filters suppress important `warnings.warn` diagnostics. They do not suppress printed diagnostics or all warning categories. Remove broad filters and selectively suppress known harmless warnings. |
| T1.4 | Confirmed unsafe fallback, qualified | `load_state_dict_robust`, line 235, tries all strict prefix variants first. Thus a pure `module.` prefix difference is already handled correctly. If all strict attempts fail, the identity non-strict attempt can return with many or all keys missing. Require complete expected key coverage for campaign checkpoints. Do not describe an ordinary prefix-only checkpoint as guaranteed to fail. |
| T1.5 | Confirmed optimizer policy; not inherently a correctness bug | AdamW receives all parameters. Decay pushes a negative gate parameter toward zero, but its effect depends on learning rate and duration. An approximate decay-only calculation using the R0 schedule shrinks magnitude by about 11.3%, moving sigmoid(-2) from 0.119 to about 0.145, not close to 0.5 during this budget. Learned gate outputs also depend on features and gradients. Explicit no-decay groups are a defensible design, but changing them changes training and cannot be postponed until arbitrary runs have completed. |
| T1.6 | Confirmed reproducibility defect | Checkpoints omit Python, NumPy, torch CPU/CUDA RNG states and the train-loader generator state. Persistent workers' augmentation states also require handling. Loading optimizer/scheduler state does not reproduce the original future trajectory. Resume errors are printed and ignored, so “all restored correctly” is conditional on successful loads. Record resume lineage and reject incompatible checkpoint/config combinations. |
| T1.7 | Confirmed conditional update-accounting defect | Both loops call scheduler and EMA updates after `GradScaler.step` regardless of whether an optimizer update occurred. AMP can skip updates on non-finite gradients. The effect is conditional; no overflow evidence was found in R0 artifacts. Gate both scheduler and EMA advancement on successful optimizer updates. |
| T1.8 | Confirmed for the current token recipe | ceil(6090/32) = 191 microbatches, accumulated in pairs. The final microbatch contains 10 images but its loss is divided by 2 despite being the sole microbatch in the last update. There are still 96 attempted updates. Fix the final group's normalization; this halves its gradient contribution, not necessarily its AdamW parameter change. This contradicts the plan's blanket statement that accumulation loss scaling is already correct. |
| T1.9 | Mostly valid defensive improvements | Explicit metric labels, class-layout validation, resume schedule compatibility, and removal of dead `_pending_budget_check` are sensible. ImageFolder fallback can mislabel an incompatible layout; it does not necessarily mislabel every alternative layout. The token CLI does have a separate strict frozen-count check, so saying it has no count guard at all is inaccurate. |

The normal successful EMA apply/restore and final best-checkpoint overlay paths do not show an EMA-twice error. One additional policy to document: EMA tracks parameters only, while HSV branches contain BatchNorm running buffers; validation uses averaged parameters with current raw-model buffers. This is not automatically invalid, but buffer handling/recalibration belongs in the declared EMA protocol.

Primary reference for skipped AMP updates: [PyTorch GradScaler implementation](https://github.com/pytorch/pytorch/blob/main/torch/amp/grad_scaler.py).

## Additional issues and corrections to the proposed order

1. **Checkpoint-write failures can silently select stale weights.** In `src/train_swin_three_models.py:668`, `_atomic_save` returns False on failure, but line 685 ignores that result for best_model. The trainer has already advanced best_val_f1. If an older best file exists, final evaluation can use it while logs describe a newer best. Both trainers share this manager. Required best/last saves should fail loudly.
2. **HSV aggregation flag is wrong.** `scripts/06_aggregate_results.py:70` reads `use_hsv`; Swin records `use_hsv_branch`. R1–R3 would consequently appear as use_hsv=False in per_run.csv unless this is fixed.
3. **Resume provenance can overwrite history.** The launcher overwrites run_provenance.json before execution, while the trainers overwrite config.json during construction before loading a checkpoint. Code/config compatibility is not enforced. A resumed run can therefore be described only by its latest invocation despite earlier epochs using different settings.
4. **The initialization diagnostic is not completely RNG-neutral.** It creates an iterator over the validation DataLoader without a dedicated generator. That can consume the global torch RNG for the loader base seed even with zero workers. Eval/no_grad protects parameters and BatchNorm statistics but does not by itself preserve RNG state. This further qualifies the plan's “side-effect-free” assertion.
5. **EMA buffer policy merits attention in HSV comparisons.** The shared EMA tracks named parameters only, while HSV BatchNorm statistics come from the current raw model. Document this policy and validate it before treating it as equivalent to averaging the complete state.

Before further confirmatory runs, settle final normalization, EMA policy, RNG controls, weight-decay grouping, accumulation-tail scaling, AMP update accounting, and resume behavior. Any change affecting weights or selection must be applied consistently within the affected comparison family. Use a new campaign identifier/output directory when changing the protocol; keep R0_s42 as the original protocol's result rather than silently mixing it into a changed campaign. Metadata-only fixes do not inherently require retraining.

Verification should include forward equivalence of the corrected C1 backbone/head to the intended baseline with copied weights and eval mode; nonzero gradient flow to the final norm; exact common-head initialization checks if promised; interrupted versus uninterrupted training under the supported loader strategy; forced evaluation exceptions; skipped AMP updates; missing checkpoint keys and failed writes; and a final accumulation group compared with its intended reference gradient. Parameter-count checks and a 24-command dry run do not cover these failures.
